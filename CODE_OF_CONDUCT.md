# Code of Conduct

## Purpose and scope

Bitcoin Core Feature Overlay welcomes constructive contributions from people of all backgrounds and experience levels. This code applies to project issues, pull requests, reviews, discussions and other project spaces, and when someone represents the project publicly.

## Expected conduct

- Treat other contributors with respect and patience.
- Critique code, claims and design choices with evidence; explain disagreements clearly.
- Welcome questions, acknowledge mistakes and respond constructively to feedback.
- Respect privacy and consent. Keep personal information and confidential reports out of public discussions.
- Keep discussion relevant to the project and give others room to participate.

Rigorous technical disagreement, including criticism of security assumptions and audit claims, is welcome when expressed respectfully.

## Unacceptable conduct

Harassment, threats, intimidation, discriminatory abuse, sexual harassment, personal attacks, deliberate disruption and retaliation against someone who reports a concern are unacceptable. Publishing another person's private information without consent is also unacceptable.

## Reporting concerns

The maintainer responsible for this policy is [Jakob-997](https://github.com/Jakob-997).

For routine moderation concerns that can be described without exposing private information, flag the relevant issue or pull request to the maintainer. For confidential concerns, use a private contact method if the maintainer has published one on their GitHub profile. This repository currently has no dedicated confidential reporting address.

If no private maintainer contact is available, or a concern involves the maintainer, use GitHub's reporting tools for conduct that violates GitHub policies. Do not post confidential details or personal information in a public issue.

## Enforcement

The maintainer may remove or edit inappropriate content, request a change in behavior, close or lock a discussion, or temporarily or permanently restrict participation, depending on the severity and repetition of the conduct.

Reports should be assessed fairly, with attention to context and available evidence. Information from a report should be shared only as needed to assess and address it; confidentiality cannot be guaranteed for public reports or reports submitted to GitHub.

Anyone affected by a moderation decision may request reconsideration from the maintainer through an available contact channel, providing relevant context without restarting the disruptive behavior.
